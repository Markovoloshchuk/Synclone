# Архітектурна документація проєкту Synclone

Цей документ описує архітектурні рішення, компоненти та схеми взаємодії сервісів у високопродуктивній системі **Synclone** (Синхронізатор пам'яті для клонів).

---

## 1. Загальна концепція та навантаження
Система проєктується як *Data-Intensive Application* (DIA), оскільки сценарій передбачає безперервний потік створення бекапів свідомості мільйонів жителів. Основними викликами є висока інтенсивність операцій запису (`high write throughput`), забезпечення низької затримки (`low latency`) та гарантія цілісності даних.

---

## 2. Компоненти системи та їх взаємодія

1. **Клієнтський шар (Client Layer):** 
   Термінали синхронізації пам'яті клонів та адміністративні інтерфейси, що генерують запити на бекап чи перевірку стану через протокол HTTP/gRPC.
2. **Шар балансування та шлюзу (API Gateway / Load Balancer):** 
   Використовується **Nginx**, який приймає зовнішній вхідний трафік, розподіляє його між нодами бекенду за алгоритмом Round-Robin та забезпечує захист від перевантажень.
3. **Шар бекенду (Application Layer):** 
   Кластер асинхронних мікросервісів на базі **FastAPI (Python)**. Відповідає за бізнес-логіку, валідацію метаданих та формування черги обробки пейлоадів пам'яті.
4. **Шар кешування (Caching Layer):** 
   **Redis** використовується для тимчасового зберігання активних сесій синхронізації та швидкого доступу до метаданих останніх бекапів, що дозволяє суттєво розвантажити основну реляційну базу даних.
5. **Шар зберігання даних (Persistence Layer):** 
   **PostgreSQL** як основна реляційна база даних для надійного збереження історії бекапів свідомості. Для роботи в умовах великих обсягів даних передбачено майбутнє партиціонування таблиць.

---

## 3. Архітектурна схема (Mermaid)

```mermaid
graph TD
    Client["Клієнти / Термінали клонування"] -->|HTTP / gRPC| LB["Nginx (Load Balancer / Gateway)"]
    
    subgraph Backend Cluster ["Шар Бекенду"]
        LB --> API1["FastAPI Instance 1"]
        LB --> API2["FastAPI Instance 2"]
    end

    subgraph Caching & Queue ["Шар Кешування"]
        API1 --> Redis[(Redis Cache)]
        API2 --> Redis
    end

    subgraph Database Layer ["Шар Зберігання Даних"]
        API1 --> DB[(PostgreSQL Primary DB)]
        API2 --> DB
    end
